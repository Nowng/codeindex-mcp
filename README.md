## Description

`codeindex-mcp` is an [LM Studio](https://lmstudio.ai/) plugin (TypeScript) that exposes the
upstream **[Code Index MCP](https://github.com/johnhuang316/code-index-mcp) — a Python-based MCP
server for intelligent code indexing, search, and analysis** — as a set of MCP tools usable inside
LM Studio.

Rather than reimplementing the indexing / search logic, this plugin ships a **lightweight
TypeScript wrapper** (`src/`) that calls each upstream tool over MCP/stdio. The upstream Python
repo is cloned at install time and left untouched, so it stays `git pull`-able for future updates.

> **Acknowledgments.** This project is a port of
> [johnhuang316/code-index-mcp](https://github.com/johnhuang316/code-index-mcp). We are grateful
> to the original author, **hoonowng** (Element Labs Inc), for creating and open-sourcing the
> excellent Code Index MCP that this plugin builds on.

## Features

- **Faithful wrapper:** every upstream Code Index MCP tool is exposed (14 tools + the
  `files://{file_path}` resource) — nothing is dropped or reimplemented.
- **Git-pull friendly:** the Python backend lives in `CodeIndex/`, untouched, so it can be
  updated with `git pull`.
- **Self-installing:** installing the plugin from the LM Studio Hub automatically clones the
  upstream repo and sets up its Python environment (see [Installation](#installation)).
- **Configurable UI:** per-chat *Project Path* / *Result Limit*, plus an optional global
  *Python Executable* override.

## Architecture

```text
codeindex-mcp/                 # This LM Studio plugin (TypeScript wrapper)
├── manifest.json              # Plugin metadata (kebab-case name: codeindex-mcp)
├── package.json               # Dependencies + "postinstall": node scripts/setup.cjs
├── src/
│   ├── index.ts               # Plugin entry point (exports toolsProvider + config schemas)
│   ├── toolsProvider.ts       # Each MCP tool = a thin wrapper around one upstream tool
│   ├── config.ts              # LM Studio config UI schema (per-chat & global)
│   └── core/
│       └── codeIndexClient.ts # Single long-lived MCP/stdio client to the Python backend
├── scripts/
│   └── setup.cjs              # postinstall: clone upstream + build venv + install deps
├── CodeIndex/                 # Upstream Code Index MCP (Python) — cloned at install time
├── skills/
│   └── codeindex-mcp.md       # Skill / guide for LLMs to use this plugin's tools
└── dist/                      # Compiled JavaScript (auto-generated by `npm run build`)
```

## Installation

This plugin installs the upstream Code Index MCP automatically via the
`"postinstall": "node scripts/setup.cjs"` entry point. When you install it from the
[LM Studio Hub](https://lmstudio.ai/) or run `npm install`, `scripts/setup.cjs` runs:

1. **Clones** the upstream repo into `CodeIndex/` (only if it is missing, so a later
   `git pull` inside `CodeIndex/` keeps working).
2. **Creates** a Python virtual environment at `CodeIndex/.venv`.
3. **Installs** the upstream's Python dependencies from `requirements.txt` via PyPI
   (run after the venv is created). No wheels are bundled, so the plugin stays small
   enough for LM Studio Hub upload.

Then load it as an MCP server in LM Studio:

```json
{
  "mcpServers": {
    "codeindex-mcp": {
      "command": "node",
      "args": ["/absolute/path/to/codeindex-mcp/dist/index.js"]
    }
  }
}
```

> **Tip:** After install, open LM Studio, start a chat, and call `set_project_path` to point the
> backend at the repo you want to index (see [Usage](#usage) and the [skill](skills/codeindex-mcp.md)).

## Development

Requires [LM Studio](https://lmstudio.ai/) (which bundles Node.js v22) plus TypeScript and `zod`.

```bash
# 1. Install dependencies
npm install

# 2. Type-check, lint, and build to dist/
npm run typecheck
npm run build

# 3. Develop with hot-reload in LM Studio
npm run dev        # == lms dev   (requires: lms server start)
```

Key commands (see `package.json`):

| Command | Description |
|---|---|
| `npm run build` | Compile TypeScript → `dist/` (`tsc`). |
| `npm run typecheck` | Type-check only (`tsc --noEmit`). |
| `npm run dev` | Hot-reload in LM Studio (`lms dev`). |
| `node scripts/setup.cjs` | Manually run the install/clone/env setup. |

To publish to the LM Studio Hub: `npm run typecheck && npm run build && lms push`.

### Re-cloning the upstream repo locally

If you cloned this plugin without running `postinstall`, clone the backend manually so the
wrapper has something to call:

```bash
git clone https://github.com/johnhuang316/code-index-mcp CodeIndex
```

## Usage

Each tool returns a readable string. A typical session:

1. **`set_project_path(path=...)`** — point at the repo (call this FIRST).
2. **`build_deep_index()`** — once, before deep analysis (`get_file_summary`, `get_symbol_body`).
3. **`find_files(pattern)`** / **`search_code_advanced(...)`** — locate files and code.
4. **`get_file_content`** / **`get_file_summary`** / **`get_symbol_body`** — read the code.
5. After edits, **`refresh_index()` (shallow) or `build_deep_index()` (deep)** to keep the index fresh.

See **[skills/codeindex-mcp.md](skills/codeindex-mcp.md for a full skill: every tool's
definition, usage rules, worked scenarios (indexing, searching, analysis, refactoring), and a
decision guide for small LLMs.

## MCP Tools Summary

All 14 upstream tools are wrapped, plus the `files://{file_path}` resource (`get_file_content`).

### Project / Lifecycle
| Tool | Description |
|------|-------------|
| `set_project_path` | Set the base project path for indexing. Call this FIRST. |
| `refresh_index` | Rebuild the shallow file index after changes / git operations. |
| `build_deep_index` | Build the full symbol index for deep analysis (`max_workers`, `timeout`). |
| `get_settings_info` | View current project config and indexed state. |

### Search & Discovery
| Tool | Description |
|------|-------------|
| `find_files` | Locate files using glob patterns (e.g. `**/*.py`). |
| `search_code_advanced` | Smart search: literal / fuzzy / regex, file filtering, pagination. |
| `get_file_summary` | File structure, functions/imports/complexity (needs deep index). |

### Code Intelligence / Reading
| Tool | Description |
|------|-------------|
| `get_file_content` | Raw text content of a file (the `files://{file_path}` resource). |
| `get_symbol_body` | Source body of one symbol (function/method/class). Needs deep index. |

### Monitoring / Auto-refresh
| Tool | Description |
|------|-------------|
| `get_file_watcher_status` | Check file watcher status and statistics. |
| `configure_file_watcher` | Enable/disable auto-refresh and configure settings. |

### System / Maintenance
| Tool | Description |
|------|-------------|
| `create_temp_directory` | Set up storage directory for index data. |
| `check_temp_directory` | Verify index storage location and permissions. |
| `clear_settings` | Reset all cached (indexed) data and settings. |
| `refresh_search_tools` | Re-detect available search tools (ugrep/ripgrep/ag/grep). |
